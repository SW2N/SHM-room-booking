A web app that replaces the yearly Excel booking sheet. Anyone with an @sahamitproduct.com email creates an account, finds a free room, and books it. Bookings are confirmed immediately, and two people can never book the same room at the same time. Everyone sees the same calendar, and it updates live.

Why it was built

The old Excel sheet had two problems:

  1. The link changed every year, so people lost track of where to book.
  2. The grid was hard to read. Free-text cells such as "Ta,Food2,RMR 11:00-12:00" mixed the person, team and time, so it was hard to see what was free and who had booked.

Creating rooms in Outlook needs an Exchange admin role that we don't have. A separate system was the practical choice.

"Being booked" (slot hold)

While someone has the booking form open, that room and time are held for them and shown to everyone as Being booked (striped amber). This stops two people filling in the form for the same slot.

  • The hold is renewed every minute while the form is open. If it isn't renewed it lapses after 5 minutes, and no hold can last more than 30 minutes in total.
  • It is released as soon as the form is closed, the booking is saved, or the tab is closed.
  • If you're waiting for a held slot, your form checks again every 10 seconds and unlocks as soon as the slot is free.
  • There's no limit on how many slots one person can hold, because team admins often book for several people at once.
Check-in, no-shows and pauses
StepWhat happens
Check inThe owner presses Check in any time on the day of the booking, up to 15 minutes after the start.
No-showIf nobody checks in by start + 15 minutes, the booking becomes a no-show and the room is released for others.
Ban2 no-shows in a row pause that person's booking for 4 hours, and all their future bookings that aren't checked in are cancelled (repeat series included). Any check-in resets the count.
What the person seesA pop-up explaining which bookings were missed, how long rooms stood empty, how many future bookings were cancelled, and when the pause ends.
AdminCan lift a pause early (Admin → Paused accounts).
Fairness rulesA booking someone was handed but hasn't seen yet doesn't count towards a ban. While paused, further misses don't add up.

A database job checks for no-shows and ends pauses every 5 minutes.

Handing a booking to a colleague

The owner can hand a booking to a colleague (for example before leave or a business trip) by entering the colleague's email:

  • This date only, or the whole series of a repeat booking. Only the person who set up the series, or an admin, can hand over or cancel the whole series.
  • The colleague becomes the owner straight away and is responsible for checking in. It appears at the top of their My bookings, under Handed to you, with a red badge.
  • A booking can't be handed over once it has started. Every handover is logged (from, to, when, which bookings).

Security
  • Only @sahamitproduct.com emails can register, and disabled people can't. This is checked by the database, not only the page. The sign-up form asks before signing in whether an email is already on the list (to skip the name/department step), which reveals whether a company email is listed.
  • A disabled account can't sign in, book, hold a slot or receive a handover, and it loses admin powers.
  • Every table has row-level security: people can change only their own bookings, and admin powers are checked on the server.
  • Pause details are private. Colleagues see only name, email, department and role.
  • The repository is public, which free GitHub Pages requires. It holds no secrets: the key in the web page is a public key, and all protection is in the database rules.
  • There is no email confirmation at sign-up. If someone registers a colleague's address, an admin removes that account (Admin → Users → Remove account), and the colleague can then sign up.
Running and looking after itadmin tasks, changes, limits

Everyday admin tasks (in the app)

  • Holidays: Admin → Holidays tab. Edit the table, or Download Excel → edit → Upload Excel → check → Save changes. Use the Year filter to switch years. Add next year's holidays before January.
  • Lift a pause: Admin → Paused accounts tab → Lift ban.
  • Staff list: Admin → Users. People who sign up appear automatically; you can add joiners in advance (or upload Excel), fix names or departments, change roles, and set leavers to Disabled. Before a disable is saved you see their upcoming bookings to hand over; the rest are cancelled.
  • Remove an account: Admin → Users → Remove account (for someone who signed up with another person's email; removes their bookings too).

Forgotten passwords

Self-service: Forgot password on the sign-in page emails a reset link to the person's own address, from "Sahamit Admin" <sahamitadmin@gmail.com>. The link brings them back to the app to set a new password.

Email setup (Supabase dashboard, tested 17 Nov 2026):

  • Authentication → Emails → SMTP settings: Gmail smtp.gmail.com, sender "Sahamit Admin" <sahamitadmin@gmail.com>. The password there is a Gmail app password, kept only in Supabase.
  • Authentication → URL Configuration: the app address https://sw2n.github.io/SHM-room-booking/ must stay allowed, or the link won't bring people back to the app.
  • If reset emails stop arriving for everyone, the app password was probably revoked or the Gmail password changed. Create a new app password in the Gmail account and paste it into the SMTP settings. Until then, admins reset passwords from the Users tab.

Backup: Admin → Users → Reset password under the person's Account status. A temporary password is shown once, to give to the person directly. When they sign in with it, they must choose their own before using the app. Use this when the email doesn't arrive.

Making someone an admin

Admin → Users → set their Role to Admin → Save changes. Nobody can demote or disable themselves, so there is always an admin.

Changing the system

Code changes go to the GitHub repository. Each push to main runs the build, and the site updates about a minute later. Database changes are migration files in supabase/migrations, with tests in supabase/tests.

Free-plan limits to know

  • Supabase pauses a free project after 7 days with no use. Daily use prevents this. After a long holiday, open the app once, or resume the project from the Supabase dashboard.
  • Email goes through the Gmail account sahamitadmin@gmail.com (custom SMTP in Supabase → Authentication → Emails). Supabase starts custom SMTP at about 30 emails an hour; Gmail allows about 500 a day. Mail from a Gmail address can land in Junk.
Known limits and ideas for later
  • Only one kind of email: the password-reset link. No booking reminders or handover notices.
  • No email confirmation at sign-up (see Security).
  • Not linked to Outlook. Bookings don't appear in Outlook calendars.
  • Free hosting. See the free-plan limits above. Paid Supabase removes the 7-day pause.
